# 项目总结

> 项目结项后的整体复盘归档。聚焦"这个项目做完了、做成了什么、留下了什么资产、下次怎么做得更好"，区别于 `01复盘总结/`（过程改进）和 `03经验输出/`（对外传播）。

## 定位与边界

| 目录 | 回答什么问题 | 触发时机 |
|------|------------|---------|
| `01复盘总结/` | 某次任务/版本哪里没做好、根因是什么、怎么修 | 任务/版本结束、触发复盘 skill |
| **`02项目总结/`（本目录）** | **这个项目整体做成了什么、有哪些可复用资产、有哪些系统性问题** | **项目整体结项时** |
| `03经验输出/` | 这套经验能否写成对外文章、公众号、分享稿 | 总结沉淀后，判断有对外传播价值 |

## 何时产出项目总结

满足以下任一条件时产出：

- 项目从 `02当前项目/` 迁入 `04历史项目/`（结项归档）时
- 项目完成一个完整里程碑（如 MVP 上线、二期验收）且后续无连续迭代计划时
- 用户明确要求"总结一下这个项目"时

## 总结文件结构（建议章节）

```markdown
# {项目名} 项目总结

> 结项时间：YYYY-MM-DD | 项目周期：YYYY-MM ~ YYYY-MM | 参与角色：xx

## 一、项目概况
- 业务背景与目标
- 最终交付范围（与立项时是否一致，差异说明）

## 二、关键成果
- 交付了什么（功能清单概览、版本数、原型数等）
- 客户/业务侧反馈

## 三、资产沉淀
- 可复用资产清单（设计模式、业务规则、技术方案）
- 已沉淀到工作区级的位置（设计库/方法论/案例库）

## 四、经验教训
- 做得好的（保持）
- 踩过的坑（在对应复盘记录中已有详细分析，此处只列主题与链接）

## 五、待办与遗留
- 未完成的需求去向（需求池/废弃）
- 后续可演进方向
```
