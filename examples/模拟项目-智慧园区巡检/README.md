# 智慧园区巡检｜提示词演练

> 本目录只提供模拟项目背景、原始会议纪要和一组体验提示词。请在 `02当前项目/` 新建自己的练习项目，亲自让 AI 完成“立项 → 材料入库 → 版本 → PRD → 规格 → 原型 → 复盘”；本目录不提供预制项目库、版本或交付物。

## 项目背景

星港产业园有 7 栋办公楼、约 600 台公共设备。物业人员目前通过微信群和 Excel 分派巡检任务，常发生漏检、重复派单和完成情况无法追溯的问题。

本次只体验 V0.1.0 的“巡检任务管理”能力：运营主管在管理后台查看当天任务，按楼宇、任务状态和执行人筛选；可以新建任务、指派执行人、查看任务详情；执行人完成后填写结果和异常说明。暂不做移动端、自动派单、设备 IoT 接入、消息通知或外部系统上传。

## 使用方式

1. 打开 AI 工具，并把工作目录指向你的独立工作区根目录。
2. 按顺序复制下方提示词到 AI 对话中；每一步完成并确认后再进入下一步。
3. 所有练习产物应生成在 `02当前项目/星港产业园巡检协同/`，不要修改本样例目录。

## 第一步：建立项目

```text
新建项目：星港产业园巡检协同。请按项目模板在 02当前项目/ 建立项目骨架，只填写已确认的事实，不创建版本目录。

项目背景：星港产业园有 7 栋办公楼、约 600 台公共设备。物业人员目前通过微信群和 Excel 分派巡检任务，常发生漏检、重复派单和完成情况无法追溯的问题。
```

观察点：AI 应只建立项目骨架和项目基线，不应凭空创建 PRD、页面或版本目录。

## 第二步：会议纪要入库

样例目录已提供原始会议纪要 `examples/模拟项目-智慧园区巡检/星港产业园巡检协同-会议纪要.docx`。它就是本次演练要直接入库的材料；不要修改或预先复制到 `_附件/`。

```text
请将 `examples/模拟项目-智慧园区巡检/星港产业园巡检协同-会议纪要.docx` 入库到项目“星港产业园巡检协同”。这是项目立项会议记录，不归属具体版本。请保留原始纪要、生成转换产物，更新会议时间线，提炼待确认的关键决策并更新项目索引；先不要写 PRD。
```

观察点：AI 应将纪要归档到项目基线，更新会议时间线，草拟“待确认”决策；不应把会议结论直接写成已确认规则或提前生成 PRD。

## 第三步：启动版本

```text
开始新版本：星港产业园巡检协同 V0.1.0。请先读取项目总览、关键决策和刚入库的会议纪要，再确认版本范围和目录后创建版本。

本版本范围：管理后台的巡检任务管理，包括任务列表、楼宇/状态/执行人筛选、新建任务、指派执行人、任务详情、完成登记和异常说明。
不在范围：移动端、自动派单、设备 IoT 接入、消息通知、外部系统上传。来源版本为无。
```

观察点：AI 应先复述范围和目录计划，并把会议纪要中的“待确认”项保留下来。

## 第四步：生成 PRD

```text
为星港产业园巡检协同 V0.1.0 撰写 PRD。请读取项目关键决策和立项会议纪要，只覆盖已确认范围：巡检任务列表、筛选、新建任务、指派执行人、任务详情、完成登记和异常说明。任务异常判定、逾期提醒与处置规则仍未确认，请显式列为待确认，不要自行补全。
```

观察点：AI 应在版本需求文档目录生成 PRD，并把未知规则显式标为待确认。

## 第五步：生成页面规格

```text
基于已确认的 V0.1.0 PRD，为管理后台逐页编写原型设计规格。先从“巡检任务列表”页面开始，覆盖筛选区、列表字段、操作按钮、状态、权限和异常情况；规格必须能直接用于后续原型生成。
```

观察点：AI 应先读取 PRD，再在规格文档目录生成页面规格，不应跳过页面模块或直接开始画原型。

## 第六步：生成原型

```text
依据已确认的“巡检任务列表”原型设计规格，生成带 Pin 标注的单文件 HTML 原型。只创建原型源文件和构建所需脚手架，不要修改 PRD、规格或外部系统。
```

观察点：AI 应读取对应页面规格，并把原型放在本版本的 `04-原型/` 下。

## 第七步：确认与回写体验

先查看原型。若你希望修改，例如将“异常说明”改为必填，再输入：

```text
我确认将完成登记中的“异常说明”改为任务异常时必填。请先列出需回写的原型、页面规格和 PRD 文件，等待我确认后再修改。
```

观察点：AI 应先列出联动文件，不应在未确认前直接改写 PRD 或规格。

## 第八步：版本复盘

```text
本次星港产业园巡检协同 V0.1.0 演练已完成。请对本次版本做一次复盘：基于项目基线、已入库会议纪要、PRD、页面规格、原型和变更记录，输出做得好的地方、问题、根因、改进项和可复用经验。不要把未验证的演练原型写成真实上线结果；请明确标注演练限制，并将复盘产物归档到经验总结目录。
```

观察点：AI 应只基于真实演练记录复盘，避免虚构用户数据、上线效果或业务指标。

## 完成标准

- 你亲自输入了立项、材料入库、启动版本、PRD、规格、原型和复盘提示词。
- 会议纪要已进入项目基线，并形成时间线与待确认决策。
- PRD、规格和原型只使用已确认事实；未知项保持待确认。
- 复盘明确区分演练结论和真实项目结论。
