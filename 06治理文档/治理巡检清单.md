# 治理巡检清单

_创建：2026-08-25 | 适用：本工作区跨 Harness AI 资产巡检 | 上位规范：《AI能力治理规范》“变更与验证”_

> 治理巡检是定期执行的独立动作，与针对单个任务的复盘分离。巡检以只读扫描为主，所有删除、迁移、覆盖类处置必须列精确目标并经用户确认后才执行。

## 执行时机

- 定期：建议每月 1 日执行一次
- 触发式：发生重大治理变更后加跑——Skill 新增、合并或退役，MCP 接入或移除，工具适配调整，install.sh 修改

## 执行方式

1. 运行只读脚本收集客观数据：`bash 06治理文档/scripts/harness-audit.sh`
2. 按下方巡检项逐项核对脚本输出与权威文件
3. 发现问题按处置纪律处理，巡检结论写入 `06治理文档/治理巡检报告_YYYY-MM-DD.md`

## 巡检项

### 1. 权威源完整性

- `.ai/skills/` 下每个技能目录都有 SKILL.md
- `.ai/agents/`、`.ai/install.sh`、`.ai/TOOL-MAPPING.md`、`AGENTS.md`、`01通用规则/AI能力治理规范.md`、`01通用规则/AI能力路由规范.md`、`00环境配置/MCP能力清单.md` 全部在位
- `.ai/skills/` 中实际 8 个含 SKILL.md 的核心目录，与 `.ai/TOOL-MAPPING.md`、`01通用规则/AI能力路由规范.md` 的可审计清单逐项一致，无缺失或多余项
- `.ai/optional-skills/test-flow-pm/SKILL.md` 与 `.ai/optional-skills/vitepress-deploy/SKILL.md` 存在，但默认不计入核心 Skill 数量
- `AGENTS.md` 只保留任务分流；项目工作流总纲、三个按需细则和 AI 能力路由规范均在位

### 2. 四端同步与链接健康

- 默认执行 `bash .ai/install.sh` 后无“非软链目录跳过”告警；需要测试时执行 `bash .ai/install.sh --with-test`；只有使用者已有独立 VitePress 站点时才执行 `bash .ai/install.sh --with-vitepress`
- ZCode、WorkBuddy、Codex（及已安装的 Claude Code）技能目录中，核心 Skill 全部为软链且指向 `.ai/skills/` 同一份源文件；启用可选能力后再核对 test-flow-pm、vitepress-deploy 指向 `.ai/optional-skills/`
- 仅 ZCode 的 `~/.zcode/agents/solution-designer.md` 是指向 `.ai/agents/solution-designer.md` 的健康软链；其余三端不安装工作区 Agent
- 各端技能目录无悬空软链（含个人技能链接，只清点报告，不自行删除）

### 3. 实体副本处置

发现非软链实体副本时：先 `diff -rq` 对比权威源，报告路径、修改时间、内容差异与缺失文件；提出迁移方案（备份后删除副本、重跑 install.sh 建软链）；经用户确认后执行。不直接删除、不反向覆盖权威源。

### 4. MCP 清单对照

- 各端配置键名与 `00环境配置/MCP能力清单.md` 登记项逐一对照
- 配置已接入但清单未登记的：补登（只记名称、用途、等级、确认门、降级方式，不记地址与凭证）
- 清单登记但配置已移除的：标注停用并注明日期
- 接入工具或状态变化的：同步更新清单和 `.ai/TOOL-MAPPING.md`

### 5. 报告归档

巡检报告（含发现问题、处置结果、遗留项）写入 `06治理文档/治理巡检报告_YYYY-MM-DD.md`，不写入 `05经验总结/01复盘总结/`。

## 处置纪律

- 删除、归档、覆盖、批量清理：列精确目标清单，二次确认后执行
- 修复顺序：先改权威源，再跑 `install.sh` 同步，最后四端验证
- 敏感信息：巡检输出不得包含地址、令牌、账号或完整请求体
