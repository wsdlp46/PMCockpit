# 错误笔记

> 记录常见失误及其防范方式。新发现应先判断是项目专属问题、通用方法缺口还是 Skill 流程缺口，再写入对应权威位置。

| 错误模式 | 典型信号 | 防范方式 | 当前落点 |
|---|---|---|---|
| PRD 膨胀且无法维护 | 一个文档混入多个范围、角色和版本 | 按主题拆分，冻结基线需求，变更新写增量文档 | `prd-writer` 与《产品需求分层与角色先行方法》 |
| 功能边界持续蔓延 | 输入清单外的功能被默认承诺 | 每项功能标来源、范围和验收；未知项进入待确认 | 项目基线、需求范围清单 |
| 角色定义滞后 | 页面已画出但看不清谁能做什么 | 先建角色边界表，再写功能和页面 | 《文档与页面资产规范》 |
| 原型、规格、需求脱节 | 页面字段或状态改变后文档未同步 | 使用确认门和三方联动清单 | 《文档与页面资产规范》 |
| 方法论无法回收 | 教训只存在于会话或单个项目 | 判断复用边界后沉淀到通用规则、案例或 Skill | 《材料与知识资产治理》 |
| 汇报遗漏关键说明 | 只列功能名词，缺少作用和边界 | 保留“做什么 + 怎么用或为什么”，并按受众表达 | 《文档与页面资产规范》 |
| 调研未确认场景就开写 | 调研范围、用途和决策定位不明确 | 先确认四项输入，再采集多源证据 | `research-pm` 与《AI能力路由规范》R03 |

## 使用方式

接到同类任务时先检查是否命中本表；若命中，必须在产出中补足对应的防范动作。不要把具体客户、报价、账号、未公开缺陷或个人经历写入本文件。
