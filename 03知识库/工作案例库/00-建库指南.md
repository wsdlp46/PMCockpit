# 建库指南

> 工作案例库的建设原则、使用方法和维护流程。既是给自己看的操作手册，也是后续提炼 agent 知识库的基础约定。

---

## 一、建库原则

### 1.1 三层结构

```
索引层 → 案例层 → 方法论层
（快速定位） （深度阅读） （跨项目提炼）
```

- **索引层**：文件路径 + 摘要 + 标签，能快速找到原始文件
- **案例层**：按[[案例模板]]深度撰写的标杆案例，包含决策逻辑和复盘
- **方法论层**：跨项目提炼的模式笔记、错误笔记，可复用的"为什么这样做"

### 1.2 写用一体

不在项目结束后专门"补"案例。而是在：
- 写 PRD 时，先查案例库找相似结构
- 做方案时，引用过往案例的决策逻辑
- 项目里程碑节点，花 30 分钟记录关键决策
- 遇到坑时，即时记录为"错误笔记"

### 1.3 渐进式完善

不追求一次做全。优先级：
1. **先建索引**（能找得到）
2. **再做样板**（2-3 个标杆案例深度写）
3. **持续打标**（新案例入库时补标签）
4. **定期提炼**（每季度从案例中提炼方法论）

### 1.4 AI 友好设计

案例模板和标签体系的设计原则：
- 每个区块有固定标题，便于 AI 做 RAG 分块检索
- "复用信号"区块提供结构化元数据
- 标签支持多维度交叉过滤
- 关键决策使用表格而非纯文本，提高检索精度

## 二、如何使用案例库

### 2.1 接到新需求时

```
1. 确定业务场景 → 查标签，找到匹配的领域案例索引
2. 确定文档类型 → 找同类型的标杆案例，看结构
3. 确定产品阶段 → 找同阶段的案例，看决策模式
4. 参考案例中的"方案概述"和"关键决策点"，而非照搬内容
```

### 2.2 撰写 PRD 时

```
1. 参考 `01通用规则/` 中现行模板与检查清单的结构框架
2. 查看案例库中同领域的 PRD 案例，理解章节组织
3. 查看"方法论笔记"中的 PRD 撰写模式
```

### 2.3 做方案设计时

```
1. 查案例库中的"关键决策点"表格，看类似场景下怎么做取舍
2. 查"错误笔记"，避免重复踩坑
3. 参考"方案概述"的论证链：场景→痛点→方案→报价
```

### 2.4 遇到问题时

```
1. 先查"错误笔记"，看是否已有类似坑
2. 如果没有，记录下来（即时写错误笔记）
3. 问题解决后，补充根因和避免方法
```

## 三、维护流程

### 3.1 入库标准

- **索引级**：任何有参考价值的文档均可入库为索引条目
- **案例级**：满足以下任一条件可深度撰写：
  - 里程碑版本（如 V3.0、V5.0）
  - 有明确的决策取舍
  - 有复盘记录
  - 可复用到其他领域

### 3.2 保鲜机制

| 周期 | 动作 |
|------|------|
| 每次项目里程碑 | 记录关键决策到案例库 |
| 每月 | 检查标签是否需要新增维度 |
| 每季度 | Review 方法论笔记，合并重复、淘汰过时 |
| 每年 | 补充工作历程时间线 |

### 3.3 版本演进

案例本身也会迭代：
- V1：初稿，项目进行中或刚结束时撰写
- V2：复盘稿，3-6 个月后补充"结果与复盘"和"失败尝试"
- V3：方法论稿，提炼为跨项目的通用模式

## 四、知识闭环

### 4.1 从案例到方法论

```
具体案例 A
具体案例 B  →  提炼共性模式  →  模式笔记
具体案例 C

具体坑 X
具体坑 Y    →  提炼根因    →  错误笔记
具体坑 Z
```

### 4.2 从方法论到工作流

```
新模式笔记  →  更新 PRD 模板/检查清单
新错误笔记  →  更新 prd-writer 自审清单/设计检查清单
```

### 4.3 四类笔记体系

| 笔记类型 | 内容 | 目的 | 示例 |
|---------|------|------|------|
| 概念笔记 | 定义、用途、边界 | 建立基础认知框架 | "什么是数据资产化" |
| 模式笔记 | 常见模式、适用场景 | 掌握"什么时候用什么" | "B端四端五角色架构模式" |
| 实验笔记 | 做了什么、为什么改、结果 | 把"做过"变成"知道为什么" | "信息架构从三角色到五角色的演进" |
| 错误笔记 | 哪里错了、为什么、如何避免 | 真正的进步来自反思 | "功能边界模糊导致范围蔓延" |

## 五、与工作区知识体系的关系

案例库是 `03知识库/` 的证据层之一，保存完整案例、决策过程和复用信号；不承担 AI 行为契约或工具本地记忆的职责。工作区级规则以 `AGENTS.md`、`01通用规则/项目工作流规范.md` 和 `.ai/skills/` 为准。

接到任务时，先从 `03知识库/_index_AI匹配.md` 判断是否需要知识大脑卡片、案例库子索引或其他证据目录；只加载命中的内容，不读取整库。案例库的 `_index_AI匹配.md` 保留为案例子路由，不作为整个知识库的总入口。

案例内容可以作为知识卡片或 Skill 资产的来源证据，但不能自动转化为结论或资产；是否沉淀由对应准入规则决定。
