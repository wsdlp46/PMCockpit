# 子 Agent 任务包规范

测试流程中可下沉子 Agent 的工种任务包。每个任务包必须定死三要素：**输入**（文件路径与范围）、**输出**（文件路径与格式）、**边界**（禁止事项）。主 Agent 派发时复制对应模板填写占位符，连同本文件一并发给子 Agent。

## 通用调度红线

- 并行不超过 2 个子 Agent。
- 长表（用例清单、逐用例结果、流水数据）一律写入文件，不整段回传对话上下文。
- 子 Agent 禁止：碰浏览器、改用例库主文件（测试方案第四节）、直接回写 `_index.md`。
- 判定结论（通过/失败等最终定级）一律由主 Agent 复核后定稿，子 Agent 产出仅为初稿或计算结果。

## 工种一：数据对平工种

**用途**：写入类轮次执行后，从流水数据表计算对平，主 Agent 免去手工对账。

```markdown
## 任务：数据对平计算

输入：
- 流水数据文件：[路径]（[格式说明：来源页面导出的表格/复制的流水文本]）
- 核对口径：源头变动 = 明细合计；具体守恒式：[如 资金池扣减 = Σ 用户入账]
- 不应变动项：[如 现金钱包余额]

输出：
- 对平结果文件：[路径，如 reports/对平_轮N_批次XXX.md]
- 格式：核对项 | 期望 | 实际 | 结论 四列表；末尾差异清单（若有不平项，列出差异金额与疑似原因）

边界：
- 只做数据计算，不做页面判定，不下"用例通过"结论
- 数据缺失时在差异清单标注"数据缺失"，不猜数值
```

## 工种二：报告初稿工种

**用途**：每轮执行完成后，从结构化执行记录生成报告初稿，主 Agent 复核定稿。

```markdown
## 任务：执行报告初稿

输入：
- 执行记录文件：[路径]（含：用例号、操作、预期、实际、截图引用、五态初判）
- 截图清单：[目录路径]（文件名即内容说明）
- 报告模板：.ai/skills/test-flow-pm/assets/exec-report-template.md
- 上轮报告：[路径]（口径观察编号续接用）；无则首轮

输出：
- 报告初稿文件：[路径，如 reports/执行报告_功能_轮N_初稿.md]
- 格式：严格按模板六节结构，编号与用例库对齐

边界：
- 逐用例结果只整理执行记录，不新增判定、不改初判结论
- 无法从记录得出的一律标"[待主 Agent 补]"，不编造
- 不回写 _index.md，不更新测试方案文档
```

## 工种三：用例批量生成工种（仅超大模块启用）

**用途**：单模块用例超过约 60 条时，按 G 组拆包并行生成，主 Agent 汇总。

```markdown
## 任务：用例组生成

输入：
- 变更规格文件：[路径]，只读第 [X] 节（[组对应的功能面]）
- 业务规则摘要：测试方案 3.2 节（[路径]）
- 编号区间：G[X]-01 起，共约 [N] 条

输出：
- 用例组文件：[路径，如 07-测试方案/_gen_G[X].md]
- 格式：编号 | 用例 | 优先级 | 关键验证点 四列表，验证点写可判定断言

边界：
- 只生成指定组的用例，不跨组、不生成存量回归组（G6 由主 Agent 全局视野编写）
- 规格中未明确的规则不臆测，列"待确认"并注明规格出处
- 不改测试方案主文件，产出由主 Agent 汇总合入
```

## 汇总要求（主 Agent）

子 Agent 产出合入前必做三查：编号与既有清单不冲突不跳号；验证点无"功能正常"式糊弄断言；跨组联动用例（G6/G7）由主 Agent 基于全局视野补齐。
