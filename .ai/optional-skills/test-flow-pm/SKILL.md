# 测试全流程（本地闭环）

从测试规划到回归复测的完整流程，产出全部本地闭环：本地执行、本地报告，不依赖 TAPD 测试模块（免费专业版无测试管理能力，不启用付费能力）。TAPD 仅在产生需研发修复的真实缺陷时按需建 bug 并关联需求，不作为流程依赖。

本流程以隔离测试场景验证过规划、用例、执行、报告与回归的闭环；使用者仍须按自己的环境、数据与授权范围重新确认。

## 分工边界（硬约束）

浏览器控制是主 Agent 专属能力，子 Agent 禁止接管浏览器与登录态会话。

| 工作 | 执行者 |
|---|---|
| 测试规划、用例编写 | 主 Agent（本 Skill 驱动）；超大模块可按 G 组拆子 Agent 并行生成，主 Agent 汇总补跨组联动用例 |
| 测试执行、回归复测 | 主 Agent 亲自（浏览器），逐步截图留证 |
| 数据对平计算、报告初稿 | 可下沉子 Agent（任务包见 `assets/subagent-taskpack.md`），判定结论由主 Agent 复核后定稿 |

子 Agent 调度红线：并行不超过 2 个；长表写文件不回传上下文；子 Agent 不碰浏览器、不改用例库主文件。

## 工作流：四阶段两确认门

```
阶段0 规划 → 阶段1 用例 →【门1：方案与用例清单用户确认】
→ 阶段2 执行（轮0 只读 → 轮1 冒烟 → 全量轮，写入操作前过【门2】）
→ 阶段3 报告归档 → 阶段4 缺陷跟踪与回归
```

### 阶段0 测试规划

输入：本版本 PRD、页面规格、项目基线关键决策、06-变更记录。规格缺失时先向用户索取，不凭原型猜测试范围。

输出：`07-测试方案/[功能名]-测试方案_V[X.X].md`，按 `assets/test-plan-template.md` 七节结构编写。

规划必须包含环境就绪检查：环境可达性与登录方式（有无验证码）、测试账号齐备性（正向角色 + 反向角色）、测试数据（资金池/基础数据是否就绪）、提测时机（研发自测期避免数据互相干扰）。就绪检查结果记入方案 4.0 前置条件节与变更记录。

### 阶段1 用例编写

- 编号 `G组别-序号`，标准组序列（按功能实际调整组名）：G1 入口与权限 / G2 核心交互 / G3 输入校验 / G4 主流程与写入 / G5 查询与明细 / G6 存量回归 / G7 异常边界。G6 存量回归组不可省，验证不破坏既有能力。
- 优先级 P0 / P1 / P2。P0 判定标准：主链路、资金或数据正确性、权限边界三者居其一。
- 编号不复用；用例合并、拆分或废弃时在清单中更新并记入方案变更记录，报告编号始终与清单对齐。
- 每条用例至少含"用例名 + 优先级 + 关键验证点"三层信息，验证点写可判定的断言，不写"功能正常"。

**【门1】用例清单与分轮计划须经用户确认后才执行。**

### 阶段2 测试执行

分轮纪律：

| 轮次 | 范围 | 启动条件 |
|---|---|---|
| 轮0 只读结构核验 | 页面结构与规格一致性，不写数据不动资金 | 环境就绪即跑，无需等提测 |
| 轮1 冒烟 | P0 主链路 + 真实小额写入 + 数据核对 | 研发正式提测 |
| 全量轮 | 用例库剩余全部 | 研发答复方案第六节待确认事项 |
| 回归轮 | 失败用例 + 受影响存量用例 | 缺陷修复完成 |

执行规则：

- 判定五态：通过 / 失败 / 部分通过 / 阻塞 / 未执行，禁止二值糊弄。
- 页面呈现与账实核对分开判定：Agent 只能验页面，数据正确性必须以流水或记录核对（守恒式：源头变动 = 明细合计；例：资金池扣减 = 全员入账之和）。
- 截图留证：`07-测试方案/reports/screenshots/轮X_序号_说明.png`，关键断言逐张截图。
- 每轮执行中同步写结构化执行记录（用例号、操作步骤、预期、实际、截图引用），落 `reports/` 或暂存文件，供报告工种使用；部分结论可引用历史轮实测，须标注来源轮次。
- 每轮启动前核对上一轮报告"下一步"清单，未闭环事项不静默丢弃。

**【门2】写入类操作（真实资金分配、调账、删除或修改数据）每次执行前向用户确认影响面（如人数 × 金额），确认后才操作。**

### 阶段3 测试报告

- 命名 `07-测试方案/reports/执行报告_[功能]_[轮次]_[日期].md`，按 `assets/exec-report-template.md` 六节结构。
- 口径观察是独立产出类别：实现与规格疑似不一致但未定性的观察项，不算缺陷、不阻塞，汇总给研发对齐；编号跨轮续接。缺陷与口径观察严格分开统计。
- 报告完成后两处回写：版本 `_index.md`（阶段状态 + 文件清单 + 最近更新）、测试方案文档的变更记录。

### 阶段4 缺陷跟踪与回归

- 缺陷本地登记 `BUG-序号`，关联用例编号，附复现步骤与证据截图位置；修复后按缺陷编号回归复测，报告续轮次编号。
- 上 TAPD 建缺陷前须用户确认目标与数量；不上传测试用例到 TAPD。

## 安全红线

- 账号凭证只存 `07-测试方案/test_accounts.local.txt`，写入前确认 `.gitignore` 已忽略该文件；报告与缺陷单引用账号时不带密码。
- 报告与缺陷单中不保留令牌、会话报文等敏感信息。
- 写入类操作仅限测试环境；生产环境一律禁止。

## 通用规则

- 测试方案头部标注依据文档（PRD、变更规格、TAPD 需求 ID）与状态（待确认 / 已确认），获用户确认后更新状态。
- 新页面或新项目的首轮测试，建议人工与 Agent 并行执行、对比判定一致率，作为 Agent 可信度评估依据；一致率数据记入报告，积累后用于评估收缩确认门。
- 模板路径：`assets/test-plan-template.md`（测试方案）、`assets/exec-report-template.md`（执行报告）、`assets/subagent-taskpack.md`（子 Agent 任务包）。
