# 竞品分析 Skill

## 触发条件

用户提到以下任意场景时触发：

- "调研竞品"、"对比XX和YY"、"市场分析"、"收费模式调研"
- "选型依据"、"帮我看看市面有哪些XX"、"竞品分析报告"
- "这个功能别人是怎么做的"、"市面上有没有类似的"

## 核心问题：为什么需要这个 Skill

竞品调研的最大痛点不是"不会做"，而是**"该停的时候没停"**：

- 该确认客户场景的时候，直接基于假设开写整篇报告 → 用户一句话推翻重来
- 该核实数据的时候，用浅层数据凑数（只查入门档、只查代表选手漏掉关键竞品）
- 该搜反例的时候，下绝对化结论（"市面零先例"），被一个反例证伪
- 该收敛方案的时候，留尾巴（"可选保留"），逼用户反复拍板

本 Skill 通过**六阶段流程 + 节点闸门**强制在关键点停下来做对的事。

---

## 六阶段流程

### 阶段零：假设确认（闸门，未确认不动手）

调研开始前，**必须先与用户确认以下四项**，任一不明确就先问，不要动手写：

1. **调研主题**：具体调研什么（收费模式？功能对比？定位差异？）
2. **客户/场景假设**：产品面向的主要客户是谁、什么使用场景（这一项最关键，错了整篇重写）
3. **报告用途**：给谁看（内部决策？对外说服？向上汇报？）——影响数据严谨度和结论呈现
4. **决策定位**：是开放评估（重评方向）还是验证既定方向（论证可行性）——影响报告重心

> 踩坑警示：基于未核实的客户假设写完整报告，是竞品调研最大的返工来源。宁可多问一句，不要写完再推翻。
> 若用户在后续对话中修正了场景假设（如"之前确认的场景是XX"），必须重新评估已产出内容是否仍成立，不成立则重写。

**确认方式**：用 AskUserQuestion 一次性问清，不要挤牙膏式追问。

### 阶段一：竞品分层选取

按"范式/定位/层级"对调研对象分层，每层选 2-3 个代表。**分层后必须做覆盖度校验**：

覆盖度校验清单（逐层问自己）：
- 这一层还有谁是代表性选手？是否漏掉了？
- 国内 vs 海外是否都有覆盖（若相关）？
- 直营 vs 聚合/平台是否都覆盖（若相关）？
- 用户点名的竞品是否都已纳入？

> 踩坑警示：常见漏选是"只查了头部一家就当代表"。例如调研企业 AI 套餐，只查 ChatGPT 就下结论，漏掉智谱、腾讯等国内代表，导致结论失真。
> 若用户点名补充竞品（如"加上腾讯""智谱也有企业套餐"），立即补查并重新评估已有结论是否受影响。

### 阶段二：数据采集

每个竞品按**统一维度**采集数据，维度根据调研主题确定（收费模式调研的典型维度：计费单元、定价结构、限额模型、超额处理、企业能力）。

数据采集的硬约束：

1. **价格必须覆盖全档位**。一个竞品有入门/中/高级/企业多个档位时，全部采集，不只写最低档。踩坑案例：ChatGPT 只写 Business $25，漏了 Enterprise $50-60。
2. **来源标注**。每条数据标注来源和时效，价格变动频繁的领域尤其重要。
3. **官方优先**。价格/功能以官方文档为准，第三方报道降级为参考。
4. **术语先确认**。遇到不熟悉的概念（如"漫剧""龙虾"），先向用户确认含义再使用，不要自行假设。

### 阶段三：对比分析

用统一维度做横向对比矩阵。**下结论前强制做反例搜索**：

反例搜索规则：
- 准备写"X 没有 Y""国内零 Z"这类绝对化论断时，**必须先主动搜一次反例**
- 搜到反例则收窄论断（"X 集中于 A 场景，B 场景无先例"而非"X 零先例"）
- 搜不到反例才能下绝对结论，且标注"基于本次检索"

> 踩坑警示：绝对化结论是竞品分析最容易被一句话推翻的部分。养成"下结论前先找反例"的习惯。

### 阶段四：选型判断

基于客户真实约束做适配评估。**区分两类"优势"**：

差异化判定规则——声称"这是我们的差异化卖点"前，先问：
- 这是我方独有、对方做不到的吗？→ 是 = 平台差异化
- 还是对方也有、只是我方也做了？→ 是 = 厂商自带能力，不是差异化

踩坑案例：把"缓存命中差价"当平台差异化，实际各模型厂商都有 prompt caching，这是厂商自带能力。

适配评估维度（根据调研主题选取，收费模式调研典型维度）：
- 客户画像匹配度
- 预算逻辑契合度
- 技术实现成本
- 渠道/分销兼容性
- 风控有效性

### 阶段五：报告输出

**结论放末尾正式章节，不前置 TL;DR**（决策型报告的偏好）。报告结构：

1. 市场主流范式提炼
2. 调研对象（我方）的场景拆解
3. 按场景的方案推荐
4. 技术内核与可选增强
5. **结论与决策建议**（正式结论章节，放末尾）
6. 附录（备查数据、来源）

**决策方案必须收敛**。给方案时不要留"可选保留""后续再说"的尾巴——要么推荐、要么明确不做。若确有保留价值，用"边界条件"形式说明"什么情况下重新评估"，而不是留成暧昧的第三选项。

> 踩坑警示：方案从"主推A"到"A为主B可选"到"明确只做A"的摇摆，说明判断不够果断。一次性给收敛的结论。

## 全局硬约束（贯穿所有阶段）

### 命名规范
- 产品/项目名称首次出现用全称，后续可用简称但全文必须一致
- 若用户纠正过名称（如简称纠正为项目全称），全文立即统一，不留简称残留

### 数据时效
- 联网采集的数据标注采集时间
- 价格/政策变动频繁的领域，提示用户"以官方实时为准"

### 自查清单（输出前必跑）
- [ ] 客户场景假设是否已与用户确认？
- [ ] 竞品分层是否做了覆盖度校验？用户点名的都纳入了吗？
- [ ] 价格数据是否覆盖全档位？
- [ ] 绝对化结论是否搜过反例？
- [ ] "差异化卖点"是否真的是我方独有？
- [ ] 决策方案是否收敛，有无留尾巴？
- [ ] 产品名全文是否统一用全称？

## 输出产物

| 产物 | 用途 | 存放位置 |
|------|------|---------|
| 数据采集表 | 原始数据底稿，带来源标注 | 项目专项放 `01-项目基线/竞品分析/`；跨项目通用放 `03知识库/竞品分析/` |
| 调研报告（完整版） | 内部深度论证，含全部数据和推演 | 与数据采集表同目录 |
| 调研报告（精简版） | 决策对齐用；面向客户时仅保留客户可感知结论 | 内部版与完整版同目录；确认对外后放项目 `03-对外材料/` |

> 产出精简版时，完整版作为证据底稿保留，两者并存。精简版是决策用的有效文档。
