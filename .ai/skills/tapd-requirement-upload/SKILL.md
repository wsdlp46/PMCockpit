# TAPD 需求上传

## 前置解析与连接器预检

执行前先解析已有上下文，不重复询问已经确认的信息。信息优先级依次为：用户本轮明确说明、当前对话已确认结论、目标版本 `_index.md` 和项目上下文。只有以下信息无法从上述来源确定时，才向用户追问：范围、端侧、目标版本。

1. **本地需求文档为必需来源**：读取目标版本 `02-需求文档/` 中已确认的需求文档。腾讯文档链接仅作来源追溯，可选；本地需求已确认时，不因缺少腾讯文档链接停止。
2. **直接上传授权**：用户明确说“直接上传”“按本地需求上传”“开始上传”或等效表达，且范围、端侧、目标版本已确定时，视为已授权上传，无需再单独索要规划确认。
3. **连接器预检**：在读取页面规格前检查当前环境是否可调用 TAPD 连接器，以及是否能读取目标 workspace 的字段配置。连接器或授权不可用时，仍可生成规划，但必须在规划和版本索引标为“上传阻塞”；不得调用创建接口、不得声称已上传、不得把问题转嫁为索要无关文档。

## 工作流（5 步）

### Step 1：加载项目上下文

按以下顺序读取：

1. 项目 `00-项目总览.md`、项目 `_index.md` 与 `02-迭代/_index.md`，了解项目和版本结构。
2. 目标版本 `_index.md`，确认本次需求、规格和 TAPD 的归属。
3. `01-项目基线/会议记录/会议纪要_时间线.md`，检查会后更新是否影响页面。
4. `01-项目基线/关键决策.md`，检查决策是否影响页面范围。

### Step 2：读取需求文档和规格文档

按已确认范围读取两类文档。

**需求文档**（必读）：

- 读取目标版本 `02-需求文档/` 的本地已确认需求，从中提取功能点、页面边界、端侧分工和状态规则。
- 如用户提供腾讯文档链接，将其记录为追溯来源；不可用或未提供不阻塞本地需求上传。

**规格文档**（逐页读）：

- 从目标版本 `03-规格文档/` 中按页面编号匹配并完整读取。
- 先判断端侧，再按语义而非固定标题校验完整性；“角色分析”“面向用户”“适用角色”等均可作为角色范围，“交互说明”“操作与跳转”等均可作为交互规则，“数据口径”“字段来源”等均可作为数据来源。

| 端侧 | 必需的语义信息 | 不适用项 |
|---|---|---|
| PC Web | 角色范围、数据范围、功能权限、交互/跳转、数据来源 | 无 |
| 微信小程序 / APP / H5 | 角色范围、交互/跳转、数据来源 | PC 专属的数据权限、功能权限枚举 |

- 只有在无法确认“谁使用、如何操作/跳转、使用什么业务数据”这三项语义信息时才停止，并报告实际缺失的业务信息；不得因规格未使用固定标题而阻塞。
- 对小程序数据未给出接口名但已明确业务对象和数据范围的，标记为“服务端业务数据，接口待研发对齐”，不得虚构接口名。

**页面分类规则**：

页面编号前缀遵循工作区统一约定。新项目按 PT/WS/AD/MP/AP/H5/OT 识别；老项目必须先读项目总览中的角色端侧约定，再沿用既有编号。

| 项目 | 老项目页面前缀对照 |
|---|---|
| 某AI模型平台 | 企业端 E*、运营后台 O*、代理端 A*、小程序 MP-E* / MP-A* / MP-P*、门户 MKT* |
| 某数据平台 | 门户 PH*、工作台 W*、管理端 A* |

### Step 3：生成规划文档

使用 `assets/plan-template.md` 生成规划。先根据需求文档和版本索引给页面标记类型：

- **存量优化**：已有活跃页面，本轮只修改局部字段、布局、文案、交互或跳转。
- **新增页面**：需求明确新增，或目标版本此前不存在该页面。
- 无法判断时，向用户确认；不得自行把存量页当作新增页重写。

| 模板字段 | 提取来源与写法 |
|---|---|
| 编号、页面名称、端侧、面向用户 | 页面规格和需求文档直接提取 |
| 页面类型 | 需求文档中的“新增/优化”标识与版本资产共同判断 |
| 数据范围、功能权限 | 仅 PC Web 页面填写；从规格语义信息提取 |
| 存量页需求内容 | 仅列本轮新增、修改、移除、受影响跳转或状态；末尾写“未列项沿用现有页面和既有规格” |
| 新增页需求内容 | 写页面信息、前置与跳转、页面元素、状态分支和关联文档 |
| 数据来源 | 优先使用规格中明确的接口/能力；无接口名时写服务端业务数据与待对齐项 |
| 相关文档 | 本地需求文档为必填，可选补充腾讯文档链接 |

**描述纪律**：

- 存量页不复述原页面全部字段、旧状态和既有流程，避免研发误解为全量重做。
- 新增页按区域写清“元素、操作、系统响应、数据来源”；不编造前后端接口和第三方支付实现细节。
- TAPD 描述使用 HTML 标签，且根据页面类型生成对应结构。

**规划文档保存路径**：目标版本 `05-TAPD上传规划/TAPD上传规划_VX.X.X_{{端侧}}.md`。

### Step 4：确认、上传与异常处理

**确认规则**：

- 用户只要求“规划”时，生成规划后等待明确上传指令。
- 用户已明确直接上传且前置解析已完整时，可在生成规划后直接进入上传；先向用户简要回显需求数量、端侧和分类映射。
- 连接器预检失败时，不进入上传，保留“上传阻塞”规划，待连接器恢复后继续，不需要重新生成规划或重复确认。

**上传前读取配置**：

1. 调用 `get_stories_fields_info(workspace_id)`，取得当前 `iteration_id`、`category_id` 和 `priority_label`。
2. 分类 ID 必须来自当前字段配置，不得沿用历史值或手工编造。
3. 分类映射不匹配时停止创建并说明需处理的分类；不可通过创建错误分类后再“当作成功”。

**逐条上传**：

每页创建一条需求；默认平级，只有用户明确要求且确有统一验收目标时才建立父子需求。

```
{
  "workspace_id": <项目ID>,
  "name": "[端侧] 页面编号 页面名称",
  "options": {
    "entity_type": "stories",
    "priority_label": "High",
    "iteration_id": "<当前迭代ID>",
    "category_id": "<当前分类ID>",
    "description": "<h3>页面内容</h3>..."
  }
}
```

**异常处理**：

- 创建失败时停止后续创建，记录已创建条目的 ID 和失败原因；不重复盲目提交。
- 分类或父子关系错误时，使用 `update_story_or_task` 设置 `is_archived:"1"` 归档错误条目后重建；TAPD 无删除接口。
- `description` 必须位于 `options` 内。

### Step 5：验证与回写

上传后使用 `get_stories_or_tasks` 按创建 ID 或精确名称查询，确认需求数量、分类、迭代和父子关系与规划一致。

将实际上传时间、workspace、迭代、分类、创建条数、需求 ID 和异常处理结果回写规划文档及目标版本 `_index.md`。未上传只能标记为“待确认上传”或“上传阻塞”，不得写成已完成。

## 上传前自检

- [ ] 已从本地需求文档确认范围、端侧、版本和页面列表。
- [ ] 已判定每页为存量优化或新增页面，存量页未复述既有功能。
- [ ] 已按端侧完成语义完整性校验，小程序未套用 PC 权限字段。
- [ ] 已预检 TAPD 连接器和 workspace 授权；不可用时已标记阻塞。
- [ ] 已从当前 TAPD 字段配置读取迭代和分类 ID，未使用猜测值。
- [ ] 上传后将按实际创建结果查询验证并回写规划。

## 常见陷阱

1. **本地需求被忽略**：腾讯文档是可选追溯来源，本地已确认需求才是生成规划的必需依据。
2. **端侧校验串用**：PC 才要求数据范围与功能权限，小程序校验角色、交互和数据；不要按固定标题机械拦截。
3. **存量页写成重做页**：存量页只列改动和受影响状态，未列项明确沿用，新增页才写完整页面说明。
4. **连接器后置检查**：先检查连接器与授权；不可用时只生成并标记阻塞，绝不宣称上传成功。
5. **分类 ID 不可编造**：必须从当前 `get_stories_fields_info` 返回值读取。
6. **描述放错层级**：`description` 必须放在 `create_story_or_task.options` 内。
