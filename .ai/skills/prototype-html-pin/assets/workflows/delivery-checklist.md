# 交付前自查清单

> 触发条件：原型画完，准备交付给用户前。新建和迭代均需执行。
> 本清单检查"是否做到了规格要求"，不预判"应该是什么"——具体字段名、列顺序、业务参数以规格文档和项目知识库为准。

---

逐项对照规格文档检查，全部打勾通过后方可交付。

## 字段一致性

- [ ] 表格/卡片的列名、列顺序、字段是否与规格一一对应，无多余、无遗漏？
- [ ] 所有输入框 label、下拉选项、状态标签文本是否与规格一致？
- [ ] 只读/可编辑/条件显示等字段状态是否与规格一致？

## 交互完整性

- [ ] 每个操作项是否覆盖了规格列出的所有按钮？是否有规格未列出的多余按钮？
- [ ] 弹窗层级（L0/L1/L2/L3）是否与规格标注一致？蒙版是否不穿透（上层蒙版必须遮住下层）？
- [ ] 筛选栏的筛选项和控件类型是否与规格一致？

## 业务规则

- [ ] 规格中明确的字段间约束关系是否实现？（如 A 是 B 的子项还是独立字段）
- [ ] 规格中明确的业务参数是否准确？（参见项目知识库中的术语定义）

## 说明文档同步

- [ ] 页面迭代后，右侧功能说明是否与当前界面一致？标注编号是否仍然一一对应？
- [ ] 对于有多个状态的组件，状态切换按钮覆盖了所有需要演示的状态？

## antd 视觉对齐（仅后台/B 端原型）

- [ ] 主色是否按"主色查询规则"取了项目主色？（不允许直接用 #1677FF 兜底）
- [ ] 组件是否复用项目本地 `_scaffold/proto-base.css` 的公共样式和 Token，仅为页面特有结构补充样式？
- [ ] Tag 状态色是否用了 antd 五档预设（success/processing/warning/error/default）？
- [ ] 圆角、控件高度、字号是否对齐 Token（6px / 32px / 14px）？

## 工具链自检（scaffold 构建）

- [ ] 用 Tailwind CDN 时是否加了 `tailwind.config = { corePlugins: { preflight: false } }`？（否则 preflight 会覆盖 proto-base.css，按钮变 16px、Tag 背景透明）
- [ ] 内联 CSS 到 HTML 后，浏览器打开是否无裸露 CSS 文本？（源 CSS 注释里不能有 `<style>`/`</style>`/`<script>` 字样，HTML 解析器遇到会提前关闭标签）
- [ ] build 产物中 SCAFFOLD 占位符是否全部替换？（grep `SCAFFOLD:` 应为 0）
- [ ] 标注开关是否用了右侧面板内的静态拨动开关（参照 annotation-demo.html 的 `#togglePins`）？禁止用 JS 动态注入到 body 的浮动按钮——定位算不准、点击效果差

## 验证手段（重要）

- [ ] 用可用的浏览器自动化或本地浏览器检查 DOM 属性、计算样式和无障碍树；有图像查看能力时，补充视觉核验。不得只凭截图判断交互是否成功。
- [ ] 验证交互时，在操作前后读取状态并对比变化；确认弹窗、筛选和状态切换均有实际响应。

---

> 发现不一致立即修，不留给用户发现。修完后再次过一遍本清单确认无新增遗漏。
