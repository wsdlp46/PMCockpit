# 底稿模板

调研原始数据的标准落地格式。每个子任务一份底稿（可含 raw 数据文件），主报告维护底稿索引表。

## 文件命名

`{类型编号}_{主题}_{日期}.md`，如 `A2_AI玩具品类与模型需求_2026-08-21.md`、`C3_跨境BotAPI合作伙伴价单_2026-08-18.md`

编号规则：A=认知调研、B=数据采集、C=操作采集、后续按需扩展。

## 底稿头部

```markdown
# 调研底稿 {编号}：{主题}

> **采集日期**：{日期}（{方式}，{检索次数}次检索）
> **服务于**：《{主报告}》第{章节}节
> **可信度标注**：直接抓取=本次成功抓取官方页面；搜索索引=搜索引擎对官方页面的索引摘要；第三方转述=非官方来源仅供参考；待补=抓取失败；锚点沿用=引用已有底稿已验证数据
```

## 正文结构

1. **一句话结论**：底稿回答的核心问题，一段话
2. **数据/矩阵表**：核心交付物，统一列头（对象、来源、计价单位、价格/数据、备注）
3. **发现与解读**：数据背后的含义，逐条编号
4. **待补/待核清单**：按优先级列出，注明原因（JS渲染/超时/未公开）
5. **来源列表**：URL + 名称 + 采集日期

## 纪律

1. 每条数据可溯源：能定位到来源和采集日期
2. 原口径保留（美元价保留美元，换算在整理稿注明）
3. 缺口显式列"待补"，不硬凑、不编造
4. 后续勘误直接追加"勘误"小节，不改写历史数据（保留变更痕迹）
5. 主报告的底稿索引表随新底稿同步更新
