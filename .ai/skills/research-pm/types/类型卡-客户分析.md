# 类型卡：客户分析

调研类型：客户分析（研究对象是"客户与市场"）。本卡为完整实例（源自某SaaS平台三客群分析任务）。

## 阶段零加问（在通用四项之上）

- 客户是谁（候选清单）；场景假设（最关键，错则整篇重写）
- 客群边界：做谁、不做谁、范围怎么切（如"不含传统后期""儿童品类不做"）
- 客户算账的单位（单条成片成本/团队月费/单台月成本）
- 拿货成本由谁提供（内部价单或指定上游）；价格口径（币种、汇率、官方价基准）
- 产物落盘位置：沿用项目已有客户分析目录；不存在时，底稿默认放 `01-项目基线/客户分析_调研底稿/`，报告放 `01-项目基线/` 并在确认定稿后更新该目录 `_index.md`

## 采集侧重

| 采集面 | 内容 |
|--------|------|
| 客户工作流与工具 | 流程环节、每环节用什么工具（订阅/自建/API） |
| 模型需求 | 按模态分（文本/图像/视频/语音）、各环节对应模型 |
| 获取渠道 | 客户实际怎么拿模型：官方直连/聚合站/中转站/订阅工具 |
| 价格 | 官方价与拿货价分离采集；全档位；可信度分级 |
| 渠道生态 | 竞品渠道（聚合平台、中转站）作为客户的可选项 |

## 洞见侧重

- 测算优先：折扣率、毛利、单台成本、包销 vs 按量
- 结构发现优先：货源分层、市场模式、价格锚
- 反例：客户"边缘化/没人用"类断言必搜反例

## 报告骨架

1. **大横表**（总览）：只承载客户是谁、常用工具与使用方式、切入点与交付方式、已确认的我方能力、责任边界、收费方式和一句话话术（列=客户，行=维度）。每格用可脱离上下文理解的短句或分点表达，不把模型清单、价格明细和渠道枚举塞入总表。
2. **分客户三节**：
   - 场景流程图或服务蓝图：每环节分工具行、模型行、获取渠道行（订阅工具、官方/API 直连、聚合站或中转站），标供货状态；模型、渠道与价格细节在此或附件展开
   - 业务分析（内部确认用，见下）
   - 营销话术（痛点/优势/商务支持三清单，逐条对应；只引用已确认的我方能力）
3. 闭环三清单：拍板（每条自解释）、待核（归上游对接）、推迟需求（进需求池）

## 能力与责任标注（全卡硬约束）

每项涉及我方、客户或合作伙伴的能力，都标为以下四类之一：

- **已具备**：可直接对外承诺的现有平台能力。
- **可协助**：可提供选型、联调、评估等支持，但不作为交付承诺。
- **规划中**：尚未建成，不能混入卖点。
- **客户或伙伴负责**：硬件、模组、固件、设备适配、客户自有系统及其项目交付等非我方责任。

总表的“我方能力”和“责任边界”必须分别表达；营销话术只取“已具备”能力，必要时单列“可协助”内容，不把它包装成平台功能。

## 业务分析五小节（内部确认口径）

1. **客户分层与目标选择**：做谁、不做谁（含理由）、市场底盘数据
2. **商业逻辑与盈利结构**：钱从哪赚、毛利结构、定价依据（含汇率/价格基准机制）
3. **货从哪来**：只写策略层（"持续找更多上游、支持国内外最新模型"），通道与成本明细指向内部采购底稿
4. **边界与关键点**：不做什么；该客户的必讲关键点（合规、计费错配、毛利例外等）单独成段
5. **竞争定位与观察项**：打什么、不打什么；什么情况重新评估

## 行文三条（全卡通用）

- 表格单元格、标题、清单条目脱离上下文要能读懂，禁压缩腔
- 高频变动数字（竞品价格、套餐档位）不写死进正文，只写结构事实
- 未建成能力标注（规划中），不混入卖点
