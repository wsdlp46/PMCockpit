# 类型卡：竞品分析

> 调研类型：竞品分析（研究对象是"我们与对手的优劣"）。本卡由原 competitor-analysis-pm skill 整体合并而来（2026-08-23），原六阶段竞品流程完整保留。通用机制（子 Agent 调度、底稿制度、洞见提炼、汇报稿规范）见 research-pm 主流程，本卡不再重复。

## 路由触发

"调研竞品""对比一下XX和YY""选型依据""帮我看看市面有哪些XX""竞品分析报告""这个功能别人是怎么做的""市面上有没有类似的"。

## 竞品六阶段流程（本卡专属，路由到本卡时按此执行）

### 阶段零：假设确认（闸门，未确认不动手）

确认四项，任一不明确先问，不写：

1. **调研主题**：具体调研什么（收费模式？功能对比？定位差异？）
2. **客户/场景假设**：面向的主要客户是谁、什么使用场景（最关键，错则整篇重写）
3. **报告用途**：给谁看（内部决策？对外说服？向上汇报？）——影响数据严谨度与结论呈现
4. **决策定位**：开放评估（重评方向）还是验证既定方向（论证可行性）——影响报告重心

确认方式：先从用户输入和项目资料提取已知项，再使用当前运行环境提供的提问能力一次确认缺项，不挤牙膏。用户中途修正场景假设时，重新评估已产出内容是否成立，不成立则重写。

### 阶段一：竞品分层选取

按"范式/定位/层级"分层，每层选 2-3 个代表。分层后做覆盖度校验：

- 这一层还有谁是代表性选手？漏了吗？
- 国内 vs 海外是否都有覆盖（若相关）？
- 直营 vs 聚合/平台是否都覆盖（若相关）？
- 用户点名的竞品是否都已纳入？

用户点名补充竞品时，立即补查并重新评估已有结论。

### 阶段二：数据采集

每个竞品按统一维度采集（收费模式调研典型维度：计费单元、定价结构、限额模型、超额处理、企业能力）。硬约束：

1. **价格覆盖全档位**：入门/中/高级/企业全部采集，不只最低档
2. **来源标注**：每条数据标来源和时效，价格变动频繁领域尤其重要
3. **官方优先**：价格/功能以官方文档为准，第三方报道降级为参考
4. **术语先确认**：不熟悉的概念先向用户确认含义再用，不自行假设

### 阶段三：对比分析

统一维度横向对比矩阵。**下结论前强制反例搜索**：写"X 没有 Y""国内零 Z"这类绝对化论断前必须先主动搜一次反例；搜到则收窄论断（"X 集中于 A 场景，B 场景无先例"而非"X 零先例"）；搜不到才能下绝对结论并标注"基于本次检索"。

### 阶段四：选型判断

基于客户真实约束做适配评估。**差异化判定规则**——声称"这是我们的差异化卖点"前先问：我方独有、对方做不到？= 平台差异化；对方也有、我方也做了？= 厂商自带能力，不是差异化。

适配评估维度：客户画像匹配度、预算逻辑契合度、技术实现成本、渠道/分销兼容性、风控有效性。

### 阶段五：报告输出

1. **结论放末尾正式章节，不前置 TL;DR**
2. 结构：市场主流范式提炼 → 调研对象（我方）场景拆解 → 按场景的方案推荐 → 技术内核与可选增强 → 结论与决策建议 → 附录（备查数据、来源）
3. **决策方案必须收敛**：不留"可选保留""后续再说"尾巴；要么推荐、要么明确不做；确有保留价值的用"边界条件"形式说明什么情况下重新评估

## 全局硬约束（本卡全程）

- **命名规范**：产品名首次用全称；用户纠正过名称立即全文统一，不留简称残留
- **数据时效**：联网数据标采集时间；价格/政策变动频繁的领域提示"以官方实时为准"
- **自查清单**（输出前必跑）：场景假设已确认？分层覆盖度校验过、用户点名的都纳入？价格全档位？绝对化结论搜过反例？差异化卖点真是我方独有？决策方案收敛无尾巴？产品名全文统一？
