# 个人使用上手指南

> 本指南面向首次使用 PMCockpit 的个人使用者。目标是在不接触真实项目的前提下，独立跑通一次“需求 → 规格 → 原型”的最小流程。
> _版本：V3.0 发行版_

---

## 1. 使用边界

PMCockpit 当前按“个人使用、统一发行”设计：

- `01通用规则/`、`03知识库/`、`.ai/` 和 `AGENTS.md` 是发行资产。使用者可以阅读和使用，但不要直接修改、push 或把改动回传到发行仓库。
- 正式项目产出只写在自己创建的项目目录中，例如 `02当前项目/<项目名>/`。客户数据、密钥和未公开材料不得进入公开仓库。
- 发现问题时，记录问题、使用场景和复现步骤，提交给发行维护者；团队协作、贡献流程和多人权限模型将在独立方案中另行设计。

## 2. 首次安装

### 2.1 获取独立工作区

本工作区应由 PMCockpit 仓库根目录的 `scripts/init-workspace.sh` 初始化。请向负责人确认你的独立工作区路径；不要直接在发行仓库或 `workspace-template/` 目录内积累业务项目。

使用 ZIP 不影响功能；只有你希望后续接收框架更新时才需要 Git。

### 2.2 安装 Skill

在仓库根目录执行：

```bash
bash .ai/install.sh
```

脚本会尝试识别 ZCode、WorkBuddy、Claude Code 和 Codex，并为每个已识别工具链接 8 个核心 Skill。看到“Skill：已链接”的数量大于 0 才表示安装成功；若为 0，请按 `.ai/TOOL-MAPPING.md` 检查你使用的工具和安装路径，然后重启 AI 工具。

只有确实需要测试闭环或维护已有独立文档站时，才额外启用：

```bash
bash .ai/install.sh --with-test
bash .ai/install.sh --with-vitepress
```

## 3. 十分钟演练

样例位于 `examples/模拟项目-智慧园区巡检/`，其中不含真实客户或业务数据。请勿直接把它当正式项目使用。

1. 打开 AI 工具，将工作目录指向你的独立工作区根目录。
2. 打开 `examples/模拟项目-智慧园区巡检/README.md`，按顺序将其中的项目背景与提示词输入 AI。
3. 让 AI 在 `02当前项目/` 建立练习项目，再依次体验新建项目、启动版本、PRD、页面规格、原型和变更回写。

演练的验收标准：能亲自用提示词触发完整最小闭环；产物落在正确的项目和版本目录；能区分已确认事实与待确认问题；能理解原型必须基于已确认规格生成。

## 4. 开始真实项目

演练通过后，告诉 AI：

```text
新建项目：{项目全称}。请按项目模板建立骨架，只填写我已经确认的事实；不创建版本目录。
```

项目骨架建好后，再告诉 AI：

```text
开始新版本：{项目全称} V1.0.0。范围是……；来源版本为无；请先向我确认范围和目录，再创建版本。
```

“新建项目”由当前主 Agent 按项目模板完成；`project-iteration` 只负责已经存在的项目的新版本、收尾和索引校正。

## 5. 日常使用的最小规则

- 做需求、规格或原型前，先让 AI 读取项目 `00-项目总览.md`、`02-迭代/_index.md` 和相关关键决策。
- 修改原型后，先确认原型，再按回写清单同步规格和需求；未确认前不能同步 TAPD、文档站或其他外部系统。
- 新材料入库时明确说出目标项目和版本；AI 无法判断归属时先确认，不要猜测。
- 客户资料、原始二进制文件和凭证按你的受控存储方案保管；框架仓库不承载敏感内容。

## 6. 遇到问题时

先依次检查：

1. `README.md` 的快速开始和当前 Skill 清单。
2. `.ai/TOOL-MAPPING.md` 的工具安装路径与调用方式。
3. 目标 Skill 的 `SKILL.md`，确认任务是否属于它的适用范围。
4. 演练项目 README 中的预期结果和排查项。

仍无法解决时，向维护者提供：使用的工具与版本、执行的命令或提示词、报错全文、发生在哪一步，以及是否可在演练项目中复现。
