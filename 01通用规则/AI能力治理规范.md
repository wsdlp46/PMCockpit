# AI 能力治理规范

_最后更新：2026-08-25 | 版本：V1.1_

> 本规范适用于共用本工作区的 ZCode、WorkBuddy、Codex、Claude Code 及后续接入工具。它规定 AI 能力的权威来源、调用边界和外部连接权限；能力触发、冲突裁决和清单见《AI能力路由规范》，安装路径见 `.ai/TOOL-MAPPING.md`。

---

## 一、核心原则

1. **一处定义，多端适配**：工作区规则以 `AGENTS.md` 和 `01通用规则/` 为权威；通用 Skill 以 `.ai/skills/` 为唯一权威源。工具本地目录只能保存软链或适配配置，不得维护同名 Skill 副本。
2. **能力分层，不互相替代**：主 Agent 负责理解任务和编排；`AGENTS.md` 规定共同约束；Skill 固化流程；MCP 提供外部系统能力；脚本执行确定性动作；工具记忆只作临时上下文。
3. **外部写入必须可控**：向 TAPD、禅道、文档站、服务器或其他外部系统创建、修改、归档、删除数据前，必须先确认目标、范围和数量，并在本地留下结果记录。
4. **敏感信息不入工作流资产**：凭证、令牌、私有地址和客户敏感数据不得写入规则、Skill、MCP 清单、工具记忆、日志或 Git；真实凭证仅存放在受控本地环境。
5. **能力不可用时如实降级**：Skill 依赖的 MCP、插件或权限不可用时，只交付离线规划、待执行清单或可导入材料，不得声称已完成外部操作。

---

## 二、能力分层

| 层级 | 职责 | 权威位置 | 不承担的职责 |
|------|------|----------|--------------|
| 主 Agent | 读取上下文、选择能力、控制交付闭环 | 当前任务会话 + `AGENTS.md` | 不替代 PM 的范围、商务和技术决策 |
| `AGENTS.md` | 触发条件、上下文加载、写入边界、确认门 | 工作区根目录 | 不承载可复用的长流程细节 |
| Skill | 固化可复用的操作流程、检查项和产物格式 | 核心 Skill 位于 `.ai/skills/<skill>/`；可选 Skill 单独登记 | 不硬编码项目业务规则、品牌参数或凭证 |
| 专用 Agent | 独立的专业判断或可并行委派任务 | 工具专属适配目录 | 不作为跨工具公共流程的唯一入口 |
| MCP / 连接器 | 访问外部系统、检索或执行已授权操作 | `00环境配置/MCP能力清单.md` 登记，实际配置留本地 | 不决定业务规则，不绕过确认门 |
| 脚本 | 执行构建、检查、转换等确定性动作 | 对应 Skill 或治理目录 | 不自行扩大写入或外部操作范围 |
| 工具记忆与运行目录 | 保存个人会话、计划、缓存或日志 | `.zcode/`、`.workbuddy/`、用户目录等 | 不作为规则、决策或 Skill 的权威来源 |

> `AGENTS.md` 不是一个独立智能体；它与当前主 Agent 共同构成工作区的总控层。

## 三、Skill 共同约束

### 3.1 权威源与命名

- 新建或修改核心 Skill，只改 `.ai/skills/<skill-name>/`，由安装脚本默认同步到四端。可选 Skill 必须单独登记启用条件，不得因目录存在而默认安装。工作区 Agent 仅有 ZCode 的 `solution-designer` 软链适配。
- Skill 名称是跨工具稳定标识，不新建仅名称不同、触发词相同的别名副本。
- 禁止在 `.workbuddy/skills/`、`.zcode/skills/`、`~/.codex/skills/` 等运行目录手工维护工作区同名副本；发现副本时先比对并迁回权威源。
- Skill 内的工作区路径使用 `<workspace>` 或相对路径，不写死个人机器绝对路径。

### 3.2 新建与修改门槛

只有同时满足以下至少 4 项时，才新建独立 Skill：

1. 已在项目中重复执行至少 3 次；
2. 包含至少 3 个稳定步骤；
3. 触发条件明确；
4. 输入和输出可定义；
5. 可跨项目复用；
6. 能明显减少人工引导。

不满足门槛时，优先补充现有 Skill、检查清单或 `AGENTS.md` 规则。

### 3.3 Skill 必备内容

每个 Skill 至少写清：触发条件、适用与不适用范围、前置上下文、输入与输出、允许写入的目录、确认门、依赖的 MCP 或脚本，以及依赖不可用时的降级方式。

### 3.4 合并与退役

- 技能合并或退役时，从 `.ai/skills/` 移除源目录后，必须扫描各工具技能目录并清理同名旧链接；悬空链接会误导触发和资产盘点。清理属删除类操作，按第七节处置纪律先列目标经用户确认。
- 第三方技能管理器（如 RedSkill）默认装入工作区散落目录（如根目录 `skills/`）的技能，必须用 `git mv` 迁入 `.ai/skills/` 并纳入 `install.sh` 分发后才算受治理；不允许长期停留在权威源之外。

## 四、专用 Agent 与子 Agent 约束

- 专用 Agent 只用于需要独立专业判断、独立上下文或并行处理的任务；普通顺序型产品工作优先由主 Agent 调用 Skill 完成。
- 子 Agent 必须被分配边界清楚、可独立完成的子任务；并行写同一批业务文件前，主 Agent 必须先划分文件所有权。
- 任何跨工具必须稳定执行的流程，不得只依赖某个工具的专用 Agent，必须提供主 Agent + Skill 的可执行路径。
- 当前 `.ai/agents/solution-designer.md` 为工具专属历史适配。是否迁移为 Skill，须在完成跨工具回归验证后单独决策。

---

## 五、MCP 与外部连接约束

### 5.1 登记要求

所有面向工作区任务使用的 MCP、连接器和外部上传通道，必须先登记到 `00环境配置/MCP能力清单.md`。登记内容只记录名称、用途、接入工具、权限等级、确认门、配置位置和降级方式，不记录地址、账号、令牌或密钥。

### 5.2 权限分级

| 等级 | 操作示例 | 执行规则 |
|------|----------|----------|
| R 只读 | 查询项目、读取配置、检索资料 | 在用户已限定范围内可执行；超出范围先确认 |
| W 可写 | 新建或更新需求、上传文件、同步页面 | 先展示目标、范围、数量或差异，获得明确确认后执行 |
| D 高风险 | 删除、归档、覆盖、批量移动、清理远端文件 | 先列出精确目标并二次确认；可 dry-run 时必须先 dry-run |

### 5.3 执行与记录

- 调用前确认连接器可用、用户已授权目标空间或项目；不可用时停止在规划阶段。
- 写入完成后，回写本地规划或变更记录，至少记录日期、目标、数量、异常和结果。
- MCP 日志不得含凭证或完整敏感请求体；运行日志默认不纳入 Git。

## 六、工具记忆与运行目录

- `.workbuddy/`、`.zcode/`、`~/.workbuddy/`、`~/.zcode/`、`~/.codex/` 下的记忆、计划、缓存和日志均为运行资产，不是工作区规范来源。
- 工具记忆不得单独保存会影响后续交付的业务规则、项目决策或通用约束。确认后的内容应分别写入项目基线、`AGENTS.md`、通用规范或 Skill。
- 发现运行目录内有旧版 Skill、过期绝对路径或明文凭证时，先记录风险并经用户确认后清理或迁移；不得自行删除。

---

## 七、变更与验证

1. 先修改权威源，再更新工具适配和安装脚本；不反向从工具本地副本覆盖权威源。
2. 每次改动共享 Skill、MCP 规则或工具适配后，至少在 ZCode、WorkBuddy、Codex 中各验证一次触发或发现状态。
3. 发现工具差异时，记录在 `.ai/TOOL-MAPPING.md`；不要把工具专属限制写入通用业务规则。
4. 治理巡检是定期执行的独立动作，与针对单个任务的复盘分离：巡检按 `06治理文档/治理巡检清单.md` 执行，配套只读脚本 `06治理文档/scripts/harness-audit.sh`，巡检报告归档 `06治理文档/`；单任务复盘记录仍落 `05经验总结/01复盘总结/`，两者不混档。
5. 修复产物涉及 Skill、MCP、Agent 的，落点必须是第三节定义的权威位置；改核心 Skill 后执行 `bash .ai/install.sh`，测试仅在确有测试闭环需求时执行 `bash .ai/install.sh --with-test`，VitePress 仅在已有独立站点需求时执行 `bash .ai/install.sh --with-vitepress`。
