# 材料与知识资产治理

> 适用：新文件、会议记录、二进制、关键决策、案例和知识库资产。执行步骤以 `project-intake-pm`、`research-pm` 和 `project-retrospective-pm` 为准。

## 一、材料入库与决策

已确认归属的新增文件、会议记录、需求或合同材料进入既有项目或版本时，调用 `project-intake-pm`。它负责类型判断、二进制转换、会议时间线、关键决策候选和索引更新；普通文档改写、项目首次创建和调研不进入该路由。

| 产物 | 权威位置 |
|---|---|
| 二进制原件 | 项目根 `_source/`、基线 `_source/` 或目标版本 `01-原始需求/_source/` |
| 转换产物 | 与原件同目录，`{原文件名}_转换.md` |
| 会议时间线 | `01-项目基线/会议记录/会议纪要_时间线.md` |
| 原始纪要 | `01-项目基线/会议记录/原始纪要/` |
| 决策候选 | `01-项目基线/关键决策.md` |
| 导航更新 | 项目总览、对应 `_index.md` 和实际归属目录索引 |

读取二进制材料优先使用 `_转换.md`；转换不完整时才回退原文。关键决策从 `#D001` 起连续编号，新项默认“待确认”，经人审阅后才能改“已确认”；后续材料使用 `关联决策 #D0XX`，被推翻项保留并链接后续决策。

## 二、知识路由

| 资产性质 | 唯一落点 |
|---|---|
| 项目专属事实、字段和业务口径 | 项目 `01-项目基线/` |
| 通用方法、流程、模板和检查清单 | `01通用规则/` |
| Skill 直接消费的参数、设计基线和模板 | `.ai/SKILL-ASSETS.md` 登记的资产槽 |
| 行业材料、政策原文、竞品事实、完整案例、研究报告 | `03知识库/` 对应证据目录 |
| 有证据、边界、反例且改变业务判断的结论 | `03知识库/知识大脑/` |

用户确认不能替代结论卡的证据标准。任务涉及行业、客户、角色、业务模式、政策或竞品判断时，先读 `03知识库/_index_AI匹配.md`；命中卡片先读结论、边界和时效，需要论证或未命中时再下钻证据。

## 三、案例沉淀与维护

项目阶段性完成、有可复用设计模式、踩坑教训或可复用决策逻辑时，由 `project-retrospective-pm` 评估沉淀。案例至少包含背景、关键决策、踩坑记录和复用信号；同领域积累三个以上案例后提炼方法论。

模板、检查清单、设计规范、设计库、方法论和术语表按其复用边界维护；政策、竞品、行业研究等变化性资料必须记录采集或核验日期。每季度或按需检查政策时效、转换产物、案例沉淀、过期内容和交叉引用。
