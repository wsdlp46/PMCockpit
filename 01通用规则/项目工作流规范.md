# 项目工作流规范

_最后更新：2026-08-26 | 版本：V3.0（总纲与按需细则拆分）_

本文件定义跨项目稳定的流程阶段、资产边界和加载入口。具体规则只在对应细则中维护，执行步骤以 Skill 为准；不得把细则全文复制回本总纲或 `AGENTS.md`。

## 一、权威分层

| 内容 | 权威位置 |
|---|---|
| 所有任务的硬约束、最小加载和分流 | `AGENTS.md` |
| 项目阶段关系与本文件所列入口 | 本文件 |
| 项目结构、版本、索引 | `项目工作流/01-项目结构与版本治理.md` |
| 材料、决策、知识库 | `项目工作流/02-材料与知识资产治理.md` |
| 文档质量、页面编号、原型联动 | `项目工作流/03-文档与页面资产规范.md` |
| Skill 清单、冲突裁决与回归语句 | `AI能力路由规范.md` |
| MCP、权限、跨端安装 | `AI能力治理规范.md`、`.ai/TOOL-MAPPING.md` |
| 可复用执行流程 | `.ai/skills/<skill>/SKILL.md` |

项目采用“项目基线 + 版本迭代”的四层结构：项目总览和索引负责导航；基线保存跨版本确认资产；每个版本完整自包含；项目级对外材料单独保存。首次项目创建使用项目模板，既有项目的版本创建、收尾和索引校正由 `project-iteration` 管理。

## 二、流程阶段

```text
项目建立 → 版本规划 → 需求 → 规格与原型 → 评审 → TAPD → 测试 → 文档站 → 收尾与复盘
```

| 阶段 | 主要产物 | 进入条件 | 关键能力 |
|---|---|---|---|
| 项目建立 | 项目总览、项目基线、迭代容器 | 用户明确立项或新建项目 | 主 Agent + 项目模板 |
| 版本规划 | 版本目录、范围清单、版本索引 | 项目已存在且用户明确启动版本 | `project-iteration` |
| 需求 | PRD、增量需求 | 范围和关键决策可确认 | `prd-writer` |
| 规格与原型 | 页面规格、HTML 原型 | 需求范围明确 | `proto-spec-generator`、`prototype-html-pin` |
| 评审 | 评审结论、修改来源 | 有待评审产物 | 变更记录 |
| TAPD | 上传规划、已确认的外部写入结果 | PRD 与规格完整 | `tapd-requirement-upload` |
| 测试 | 用例、报告、截图 | 已提测或用户明确测试，且可选能力已显式启用 | `test-flow-pm` |
| 文档站 | dry-run、同步记录 | 原型确认、站点已配置且可选能力已显式启用 | `vitepress-deploy` |
| 收尾与复盘 | 状态校正、复盘、总结 | 版本完成 | `project-iteration`、`project-retrospective-pm` |

评审结论进入版本 `06-变更记录/`，被评审文档必须标注修改来源。原型确认前不得同步规格、需求、文档站、TAPD 或外部系统；确认后按页面资产规范列回写清单并获得明确指令。

## 三、按任务加载

| 任务 | 必读规则 | 补充输入 |
|---|---|---|
| 首次创建项目 | 项目结构与版本治理 | 项目模板、知识库匹配索引 |
| 启动或收尾版本、维护索引 | 项目结构与版本治理 | 项目总览、迭代索引、来源版本 |
| 入库材料或会议纪要 | 材料与知识资产治理 | 项目或版本归属 |
| PRD、规格、原型、TAPD、对外文档 | 文档与页面资产规范 | 关键决策、对应业务输入 |
| 调研、案例沉淀、领域判断 | 材料与知识资产治理 | `03知识库/_index_AI匹配.md` |
| 测试、部署或外部写入 | AI能力治理规范 | MCP 清单、对应 Skill |
| 多能力冲突 | AI能力路由规范 | R01–R11 裁决表 |

进入既有项目时始终读取项目 `00-项目总览.md` 和 `02-迭代/_index.md`。关键决策、最新会议和上述细则只在任务涉及对应事实或操作时加载；不再为普通文案调整加载完整工作流资产。

## 四、跨阶段不变量

1. 基线只保存跨版本确认资产，版本保存本版本产物；继承资产不等于本版本完成。
2. 项目首次创建与版本创建分工独立：前者用项目模板，后者调用 `project-iteration`。
3. 外部写入前确认目标、范围、数量；删除、覆盖、归档和远端清理须二次确认。
4. 关键决策、需求、规格、原型、变更记录之间必须可追溯。
5. 规则只在一个权威位置定义；AGENTS.md 只保留触发和硬约束，Skill 只保留执行流程。
